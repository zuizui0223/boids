**2026-11-08 JST**。本物のWageningen Marine Research (WMR) WS3 GeoServer WFS公開レイヤー `WS3shp:ws3_ecotope_mp_litoral_zones_and_dynamics`、および出版者MD5＋原SHA256で確認したNIOZ **2010年1月の486×820＝398,520真正緯度経度モデルセル**を照合。[元公開GIS原本Actions #42459421408](https://github.com/zuizui0223/boids/actions/runs/42459421408) **SUCCESS、16件の元GIS/known-truthテストPASS（v84C6、v84 5、v83B 5）**。**元野生GPSの位置使用順位、個体ID、公式潮位の再計算、摂食/採餌効果のいずれも本段階では見ていない**。これはデータ品質と生息地対照のソース成立である。

## 1. 正しい公開WFS原本全件取得、偏った一部のポリゴンだけを使わない

v83で当初のMendeley2021年訂正済みv2 GeoPackage（DOI 10.17632/27mysx289g.2）は公式匿名APIで**401 Unauthorized**を返した。v83BではWMRの真の原OGC WFSに `litoralcode` と `dynamiccode` があることを確認したが、**そのレイヤーがMendeley2021訂正済みv2そのものとは元メタデータから断定できない**。v84の `CQL_FILTER`（潮間帯3/4をサーバーで事前抽出）は、全リクエストに HTTP500。別に凍結したv84B診断[#42459072702](https://github.com/zuizui0223/boids/actions/runs/42459072702)で、**フィルター無しの原GetFeatureはHTTP200**、原サーバーが報告したpolygon数はSchier **345**、Ameland **280**であると判明。

今回は**ソースを開く前に**[v84C事前固定仕様](V84C_FROZEN_WMR_UNFILTERED_ALL_POLYGONS_SOURCE_LOCAL_MIDHIGH.md)として、同じ元の島周辺bbox・同じ本物のWFSレイヤーの全件を **CQL無し count=800** で1回取得し、元 `numberMatched` と実際のfeature件数が**Schier345=345／Ameland280=280**と完全一致する場合のみ使用すると決めた。本物の元結果は**両島とも一致、欠落・途中切り捨て無し**。公開元WFS response SHA256をローカル算出したが、これは出版社側の事前公表SHAではない。元ポリゴンの完全な座標自体はレポートへ保存していない。

## 2. 元の生息地コード3・4を厳密に抽出し、NIOZ元2010年格子へ重ねた

WMRの元 `litoralcode` は0〜6。今回**中位潮間帯のコード3（代表的な干出比率25–75%）と高位潮間帯のコード4（75–85%）だけ**をソース候補にした。低位潮間帯コード2の浅海境界には2019年v1と2021年v2で訂正差があるため、使用しない。**塩性湿地コード6**は休息等に使われる可能性があるが、今回は厳格な「中位/高位潮間帯」背景から外す。陸・水域・塩性湿地・低位潮間帯が生物に無用とは断定しない。

**この数値はモデル・空間分類のソース量であって、鳥が実際にいた位置が全て潮間帯だったという意味ではない**。同時期の本物の底生動物の餌量・実干出時間・現地標高・採餌行動はまだ測っていない。WMRの2008–12年の複数年構成地図の分類とNIOZの2010年モデル数値には一部共通の海洋環境・流体モデルという背景があり、完全に独立した物理場ではない。

## 3. 何が次の「生物学的な反証」になるか

以前のv75〜v82では、元の実際のGPS地点のNIOZ `time_expo` 数値が周囲1kmの**全モデルセル**の中で相対的に高いという結果が出た。しかし全モデルセルには永久水域、陸、休息地、塩性湿地など**鳥がその瞬間に採餌できるか未検証な場所**が混在している。地理的に中高位潮間帯コード3/4の格子だけに絞ると、従来の空間順位が弱まる・消える・逆転する可能性があり、これこそ機構解釈に重要である。

次に**別に凍結した事前ソースゲートを持つv85**を新しく作るべきである：
- **先に**2010年野生GPSでコード3/4の格子に実際に位置した元個体数と、個体×月×実測RWS潮位×上げ下げ×昼夜の4条件が成立するかだけを確認する。この段階ではGPS地点の元 `time_expo` 使用順位を読まない。
- 両島とも既存の個体数・潮相・0.2m潮位階級の固定基準を満たした場合だけ、**GPS地点も背景格子もコード3/4だけ**の条件付きの相対順位を新しい主指標にする。旧い「周囲全セル参照」とは別の母集団/応答であり、直接の効果量の大小比較も慎重に行う。
- **ソース成立しない場合は、鳥が本当は高い干出セルに出現しない／観測努力が足りない／休息・採餌地点が別である可能性を示す元データ品質結果だけ**とし、新しい潮汐×明暗の生物学的差を作ってはいけない。

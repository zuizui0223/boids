# v75 肯定的な原野外GPS結果：ミヤコドリの実測地点は周辺より高いNIOZモデル潮汐曝露指標の場所に偏る

**2026-11-08 JST、原本Zenodo・NIOZソースGitHub Actions [#42441470911](https://github.com/zuizui0223/boids/actions/runs/42441470911) SUCCESS**、v75 known-truth 6件＋v74元ソース4件の**計10件テストPASS**。v74の12月分ソース適格性結果を踏まえて、**実際の利用地点のモデル数値を評価する前に**[v75固定仕様](V75_FROZEN_ORIGINAL_2010_TIDAL_MODEL_USED_PIXEL_LOCAL_RANK.md)をコミットした。ただし、v43–v74の同じミヤコドリコホートに多くの探索的研究をすでに行っており、これは「最初の標本開封前の予備登録」ではなく**事後の新しい探索的フィールド関連検定**である。

## 1. なぜこの結果はv69/v70と違うか

v69・v70は、GPSの次方向（数十分〜数時間）を「潮汐×太陽高度／日長」または「過去12時間の低潮位×日照重なり」で**追加予測する**モデルが改善しないという結果だった。今回は次方向を推定しない。**同じ2010年の鳥が実際にいた位置**を、**同じ月のNIOZ独立数値流体モデルの潮汐曝露指標の地理分布**と結び付け、その周辺の数値格子と比較する。

NIOZ元ファイルの `time_expo` は元READMEに*tidal flats の exposure time* とあるが、オリジナルNetCDFの単位属性が欠損し、値0–1の意味（割合・相対尺度等）が元READMEから一意に確定しない。そこで**使われたセルの相対順位**を使い、単位を時間と見なしていない。このモデルは**月別の空間流体モデル**であって干潮時刻の実測でも、地盤高実測でも、餌生物・本当の採餌時の観測でもない。

## 2. 元個体・元月・モデル値を先に固定

Zenodo `O_SCHIERMONNIKOOG-gps-2010.csv.gz` の2010年282,920原GPS測位を出版者MD5および原本SHA256 `8d7d0ac9cef0935e7351bcf9a525c0f9eeb7605dc603d227f9b09744dadd532d` で検証。v74ですでにソース適格と確認済みの**2010年08〜12月の5か月すべて**を、モデルの使用位置の相対順位を見ずに採用。各月NIOZ原 `eco_av.2010MM.nc` を出版者MD5と元v74検証の固定SHA256で全件再照合。各月の原モデル 486×820 = **398,520元格子セル**は真の元緯度経度と数値 `time_expo` が存在する。2010年1〜5月は原鳥3羽/各月しかいない、6〜7月は月別元NIOZ緯度が完全欠損という**ソース失敗を維持**。欠損月や2011年を推定して加えていない。

同一個体×1時間につき正しく元最初のGPS位置1点、モデル原セル距離≤300m（5か月すべてのGPS原位置100%）、原位置から**1km**内のモデルセル≥20、個体×月≥20個体×時間観測という事前固定のソース品質条件にすべて合格。元月の位置数は8月11,427、9月9,572、10月9,508、11月7,975、12月6,656の**45,138**。個体×月に20位置以上の条件を適用後、順位計算に使用した原位置は**45,064**。個体×月の有効組は**68**、これを**16個体**に束ねて推定した。45,064箇所を45,064羽の独立生物標本と扱っていない。

## 何を固定して確認するか

- Rスクリプトを元ZIPから再取得し、**原Rファイル本体のSHA256**を取得。元の26MB CSVメンバーSHAと完全一致を再確認。
- 元R行から実際のCSV/RDS/XLSXなどのデータ読み込み／加工／フィルタリング／時刻グリッド再構成／ゼロ埋め／サイトID名・年月条件・モデル呼び出しの**字句的な存在数**を記録。
- 元作者のソースコード本文・個人ローカルパスをGitHubへ丸ごと転載しない。source-safeの関数トークン・コード行番号・元参照ファイルのbasename・ソースSHAのみ保存。
- **注意：コードに単語があることは実際に実行された証明ではなく、単語が無いことは元C-PODが稼働努力を記録していなかった証明でもない。** 元CSVにはclicks=0が1行もないという事実は元v158–159で確定済み。元生データ(CP1/CP3)にゼロクリックの稼働時間が存在するかは原生ファイル/デプロイメントログが必要。

## なぜこの順が論文の価値につながるか

既存の共起時系列を無制限に再解析するより、元の観測努力とSITEコードの意味を確定しないまま「全球に普遍的な時間ニッチ」と主張する危険を先に排除する。真正ソースの整合性が確認できれば、独立海域へ持ち込める予測対象・分母を明確に定義してから、新たな公開データを追加する。

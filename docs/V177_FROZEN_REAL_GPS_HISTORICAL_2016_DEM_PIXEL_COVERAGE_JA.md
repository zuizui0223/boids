# v177：真正ミヤコドリGPSを2016年ラベルの歴史Vaklodingen地形有効セルに対応させられるか（結果前に固定）

2026-11-17。Vlielandでのミヤコドリ *Haematopus ostralegus* の元2018/19年GPS・加速度計行動分類と実際のRijkswaterstaat Vlieland Haven港水位から、自己の直前15分状態の予測情報と、港水位「高さ」の年外追加予測情報が存在することをv166–169で確認した。しかし水位が干潟への物理的アクセスを切り替えるために予測が改善したという機構は、**鳥の個体別GPS地点の歴史的地盤標高を直接照合していない**ので未証明。

v170でBorndiepという別海域の2016/19年原元NetCDFをVlielandに誤対応させる危険をSOURCE STOP。v171/172/173でDeltares公式NetCDFの真の地理範囲から10枚の歴史タイルに絞り、v174/175で元\`time\`・\`z\`・\`isource\`・EPSG:28992を確認、v176で**2016-01-01ラベル層に非欠測の標高zが10枚で計1,881,902セル**あることを原OPeNDAPから実際に取得・照合した。

## v177の独立したSOURCEゲート（新しいGPS対応結果を開く前に固定）

元sourceを取り直し、v168の固定メンバーMD5・公式水位月別response SHA256に照合。2018年SOURCE **193,088**個体×15分ビン（真の直前15分も実観測された入場対象**157,863**）、2019年**155,387**元ビン（入場対象**125,241**）の個体ID・時刻・GPS位置を、元Zenodo O_VLIELAND original dataから一時的なGitHub ActionsのRAMへ復元する。v168のSOURCE分母、同じ鳥の前15分native UTC窓、RWS0/+3/+7/+11日にすべて実測がある機会を**変えない**。

すべての元WGS84 GPS位置を元EPSG:28992 / Amersfoort RD Newへ\`pyproj.Transformer(always_xy=True)\`で変換する。v173の10タイル各\`x\`と\`y\`を実元NetCDFから取得し、真の**20 m格子のセル中心**に半セル幅（最大10 m）以内で対応する場合だけ候補とする。**標高がないセルへ最近隣の別有効zを補完しない**。複数タイルで同じGPS点を候補とする曖昧セルも、都合のよい標高を採択せずSOURCE STOP扱い。

各タイルでは、v175の真の\`time\`で\`2016-01-01\`ラベルがある**ちょうど1層だけ**の元\`z[y,x]\`と\`isource[y,x]\`を読み、v176で検証した非欠測zとsourceコード数が**元の315万格子（10×312,500）の元SOURCE QCと完全一致**するか検査。その後初めて**GPSに対応するセルで\`z\`と\`isource\`双方が非欠測か**を数え、2018・2019年別、6〜9月別、元10タイル別、SOURCE対象鳥数だけを原SOURCE-safe JSONに保存する。

### 結果前に固定したGPS入場条件

- 2018年の元157,863 SOURCE binと2019年の元125,241 SOURCE binが**一件も増減しない**。
- **各年20,000個体×15分bin以上**で、2016年ラベル層の元有効\`z+isource\`に一意に対応すること。
- 各年**異なる標識鳥10羽以上**にSOURCE有効地形セルがあり、元6–9月のうち最低**3か月**に有効GPS対応があること。
- 1個体GPS座標を複数タイルの20m格子として採択するような曖昧性が**ゼロ**であること。
- SOURCE不足なら明示的にSTOPし、潮位での予測改善に都合よく閾値を緩めない。

元10タイルの標高の分布は場所により深い海底（−25 mなど）も含むので、有効zに対応したから干潟で採餌しているとは限らない。GPSでのzの中央値・5/95百分位は**元datum未独立検証のSOURCE QCとしてのみ**保存し、干潟露出率や水深をここで計算しない。

## 特に残す不確実性

1. 元2016時間ラベルは年度スナップショットであり、そのセルが本当に2016年に船測量された日や、同一\`isource\`コードの測量起源を単独で特定したことにならない。zが元層に非欠測でも**2018年時点の真の局所地盤高さとは限らない**。
2. 元\`z\`は\`m\`、水平CRSはEPSG:28992だが、**元DEMの鉛直基準がRWS港水位のNAPと同一だとまだ独立検証していない**。水平座標系が合うことと縦の水位基準が合うことは別の問題である。
3. RWS港の実測水位は鳥GPSの採餌地点での局所水位ではない（従来最大25 km）。水位の振幅・位相差、潮流、餌密度が未観測で、GPS点で\`h_\mathrm{local}-z\`をまだ実測していない。
4. 同鳥の前15分行動分類Yは保留2019年の当該時刻の前に既に観測されたものとして与える**オンライン条件付きnowcast**。原2018年で2019全部を予測する完全な前年度予報とは異なる。
5. SOURCEのGPS点は各15分binの元ACC分類の最も早い時刻に同鳥GPSと対応させた位置であり、全15分の鳥の真の採餌位置・実際の餌摂取時間ではない。

この版は**実測元GPS×元2016 DEM標高の地理学的入場監査**のみ。予測MSE、潮位高さの因果解釈、干潟干出面積、個体間Boids運動力は一切新しく推定しない。元の個体ID、GPS点座標、source UTC分類時刻、2016年元DEM rasterをGitHubへ再配布しない。

## 原本・手法・再現

\`validation_v177/real_GPS_to_2016_DEM_source_gate.py\` は、v168真正2018/19 SOURCE→同一鳥前15分の対象抽出、\`pyproj\`座標変換→公式10タイル2016z/isource元mask一致→年/月/tile単位のSOURCE統計だけを生成。合成テストは20m中心の正負・欠損・タイル境界と元time index一致を確認。

GitHub Actionsは元v128/v129/v126/v127の成功artifactの**匿名SHAレシートだけ**を先に取得し、Zenodo元GPS/ACCとRWSの実測全8か月を再取得してバイト証明。その後、真の2016層だけをOPeNDAPで一時ロードし、SOURCE統計だけを出す。実データ全点の時刻・座標・zは保管しない。

SOURCEが通れば次の研究は元datumの外部文書検証＋原測量年差の評価、その後にだけ\`h_\mathrm{local}(s,t)-z(s)\`と正しい潮汐位相対照との関係を年外評価する。**潮汐×太陽の生物学的因果平均効果と直接Boids社会力はNOT_ESTIMATED**。

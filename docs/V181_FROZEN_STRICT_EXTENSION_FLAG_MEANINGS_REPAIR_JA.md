# v181：CF flag_meanings のファイル名内空白を保護するSOURCE監査（探索的・結果前固定）

2026-11-17。v179原GPS→DEM対応149,446/119,778件再現、しかし`isource.flag_values`対`flag_meanings`を単純空白分割した結果、**両年とも0件しか出典年が解決されずSOURCE_STOP**。失敗はそのまま残す。

v180で真正元Deltares 10タイルの属性のみ照合したところ、コードと単純空白分割の出典名が同数なのは **2/10タイル**。残り8タイルは1〜2個ファイル名トークンが余った。ファイル名内部の空白が原因という仮説を、元GPS結果を再閲覧する前に具体的に修正する。

## 固定ルール
- 元`isource.flag_meanings`生文字列を、`.asc`・`.txt`・`.xyz`・`.csv`・`.tif`・`.dat`（任意の`.gz`）**拡張子の直後に空白または末尾がある位置**でのみ分割。ファイル名途中の空白は保持する。未消費の末尾文字列、未知拡張子、重複・欠損コード、コード数と完全ファイル名数の不一致はそのタイルの対応を拒否する。数字の順序だけで出典年を補わない。
- 先行v178/v179とまったく同じ真2018・2019原GPSと各年同じ直前15分レコード、同一画素における最新の過去6年レイヤーを使用。v178の完全一致数2018=149,446・2019=119,778を不変とし、不一致ならSTOP。
- 年判定閾値はv179から変更せず、観測**前年以前**と元ファイル名で確認できた位置が各年20,000個体×15分ビン以上、個体≥10羽、6〜9月から≥3か月、タイル重複0。**有効な元ファイル年でも真の測量日とはみなさない。**
- ある画素の最新地形出典年が不明/未来でも、都合よく旧地形へ差し替えて回避しない。
- 出力は年・月・元ラベル年・出典ファイル名年の集計と同一出典判定のみ。元GPS位置、鳥ID、個体別ACC、水位、生のDEM画素は一切公開しない。
- v179失敗後の**パーサー修正・探索的感度実験**として結果を扱い、未開封確認的な因果仮説検定へ格上げしない。

**局所干潟の干出、水深、採餌機構、潮汐×太陽の生物因果、群れのBoids力は今回も推定しない。**

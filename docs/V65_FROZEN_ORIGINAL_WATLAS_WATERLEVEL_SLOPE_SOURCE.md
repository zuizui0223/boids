## Reason for the distinct source-only method

In the WATLAS publication the original `tidaltime` is "time past high tide", but the sign convention in the supplementary data must not be assumed to contain both negative and positive values; the physical flood/ebb direction of gauge water level should instead be audited directly. Original `waterlevel` is a published gauge-associated value in **cm at West-Terschelling** with authors' tidal timing information, **not** measured waterline or physical resource exposure at each GPS location. A tide-gauge slope is a source-derived physical time covariate, not a direction outcome, and does not identify tidal causation.

## Original observation and phase construction, absolutely no future direction outcome

1. Verify original Figshare provider supplied/computed MD5, published size, fixed SHA256, expected original schema and v64 source raw counts. Only original accepted QC rows (NBS>=3, original localization variance each [0,5000]m², finite UTM31 X/Y, valid 2017–2023 UNIX time). Never fetch or simulate new positional observations.
2. Rebuild original **30-second TAG×time bins** exactly as v64, averaging only same-bin valid XY positions; preserve tideID only if unique and nonempty, numerical `tidaltime` and `waterlevel` only if finite within-bin spreads ≤2 min and ≤5 cm. Aggregate `tidaltime` range, median and p05/p95; number of negative, zero and positive accepted original-bin `tidaltime` entries. These are source-format diagnostics, never model effects.
3. Independently pool all original TAG bins' **published waterlevel at their original bin-start times**, grouped by the SAME original `tideID`; the gauge field is shared and observations of different tagged birds can supply the two **water-level reference times**. Never use B→C heading/target. For each original tideID create time-sorted unique bin-start timestamps and the **median reported waterlevel** at each timestamp. If the spread between different birds' simultaneous original waterlevel reports is >5 cm, that timestamp cannot serve as a reference.
4. For every candidate original B time within tideID, find the deterministic *closest to a 30-minute lag* gauge timestamp in the windows **10–50 minutes BEFORE** and **10–50 minutes AFTER** B (each source time must be genuinely present, same tideID). Tie-break by earlier source time, and never interpolate/extrapolate missing source observations. The physical proxy waterlevel rate is `(height_after - height_before)/(elapsed_seconds/3600)` in **cm/hr**. Classify `rising` for rate **>= +3 cm/hr**, `falling` for rate **<= −3 cm/hr**, and `slack/unknown` otherwise. This source-derivative sign (unlike v64 `tidaltime` before/after label) is a new estimator and is **not formally cross-validated against an independently obtained official RWS gauge file**. The published West-Terschelling sample is opportunistically observed by bird tags, so a bracketed original-waterlevel series may be too sparse for representative tide cycles.
5. Use exact unchanged v64 2019 WATLAS source-only moving triplet admissibility: same-tag consecutive original Binned A→B→C (both B-time gaps 30–180s, all 3 positions same original tideID, both absolute step speeds 0.2–30m/s, original B `waterlevel` and `tidaltime` present). B→C distance magnitude can be read *for source eligibility*, but **do not compute its angle or predicted direction**. For each source-quality eligible B, attach only its tideID waterlevel derivative class rising/falling/slack/no-physical-bracket. Count source-stage denominators and phase/tideID/tag support. Do not drop difficult times/animals to chase positive effects.
6. **No new ecological effect in v65.** A species may be labelled `SOURCE_FEASIBLE_FOR_FUTURE_INDEPENDENT_TIDAL_SLOPE_FORECAST` only if after the above SOURCE-ONLY procedure there are **>=120** non-slack physical-source-labelled A→B→C moving triples, **>=3** distinct contributing TAGs, **>=4** original tideIDs, **>=30 rising** and **>=30 falling**, **>=2 tideIDs for each phase**, and **>=2 tideIDs with >=20 such original triples** for future tide-cycle holdout. These six criteria (same numerical source thresholds as v64 but physically different new phase gate) are frozen before audit and not relaxed after results.
7. Record source metadata consistency and stage failure causes. Publish only counts/quantiles/tideID numbers and provider digests; **never raw TAG IDs, UTM coordinates, precise times, per-animal source indices or speed/direction trajectories, raw waterlevel series or personal identifiers**. A pass would only justify a separate future **v66 prediction specification**, with physically independent RWS gauge corroboration and true held-out tideIDs before scoring actual next-direction. A failure is `NOT_ADMITTED`, not absence of ecological tidal behaviour, and does not annul v43–v63 historical positive oystercatcher predictive results.

## Crucial time-resolved spatial ambiguity

Rijkswaterstaat's 20m horizontal NAP bathymetry `WadGrid 2009–2014` combines different basin survey years: **Marsdiep 2009, Eierland 2011, Vlie 2010, Ameland 2011, Friesche Zeegat 2012, Groninger Wad 2013, Ems-Dollard 2014**, according to the published Digitale Systeemrapportage Waddenzee data source. [Provider description](https://www.systeemrapportage.nl/wadden/data.html). Accordingly **never use a final 2009–2014 raster as if entirely observed in 2010**, especially Schiermonnikoog around Friesche Zeegat/Groninger Wad. Geographic basin mapping and original pixel's survey date are required; 2010 GPS may be joined only to truly observed **year ≤2010** bathymetry or explicitly labeled lagged prior-2003–2008 survey. If source year unknown or newer than test year, mark **NOT_ADMITTED**. The current RWS national live 2026 raster, even if WCS accessible, is **not a substitute** for 2010 source.

Source documentation (not yet authenticated original bytes): [Wadden source survey-year table](https://www.systeemrapportage.nl/wadden/data.html), [Deltares original NetCDF THREDDS catalog](https://opendap.deltares.nl/thredds/catalog/opendap/rijkswaterstaat/vaklodingen_new/catalog.html). THREDDS catalog access may be unavailable; never guess NetCDF tile names/paths or provenance.

Independent physical alternative **NIOZ** DOI [10.25850/nioz/7b.b.n](https://doi.org/10.25850/nioz/7b.b.n), *3D high resolution numerical simulations of the hydrodynamics of the Dutch Wadden Sea (hindcasting 2009–2011)*, Duran-Matute et al., original monthly `eco_av.YYYYMM.nc`, ~13.7MB each, stated horizontal 200m resolution, NIOZ original CC0 public archive, model output **not measured RWS gauge nor observed GPS**. Source is time-matched in year but **do not assume monthly files contain 10-min, 1h or other true within-tide time steps**: a monthly-average model field is NOT a source of rising/falling flood phase. Do not confuse the 200m resolution *space* with temporal resolution. Check actual file original dimensions, variable meanings and units.

**Source-only checks**:
- Manifest publisher data identifier, number of monthly netCDF files (expected 36 for 2009–2011) and 1 README, MD5/byte count for two frozen original month files.
- Use `xarray.open_dataset(..., decode_times=False)` and `netCDF4` to print ONLY anonymous structural aggregate (dimensions, coordinate variable names, time numeric-unit/description without raw arrays, variable metadata units and long_name, exact global spatial metadata/coordinate reference if present). Never publish full 2D/3D model fields or original raw point positions. File-level source score `TIME_RESOLVED_WITHIN_TIDE` iff a real model time dimension has **≥24 distinct sequential timestamps per month with median cadence ≤60min**, both months, and a plausibly named original sea-surface height, total water depth, wet/dry mask, or stationary bathymetry variable can be identified *from its original metadata*. This is only source feasibility, not phase calibration.
- Source spatial admission must establish (a) true original coordinate reference/datum or explicit spatial geolocatable lat/lon coordinates, and (b) 2D model grid bounding-box overlap with original Schier and Ameland reference gauge latitude/longitude. If model coordinates are projected, first explicitly identify CRS; never interpret Easting/Northing directly as longitude/latitude. A genuine model result requires checking original RWS gauge tide phase and heights for same dates, and sampling actual original GPS at appropriate time. Those tests belong to later preregistered endpoint only.
- If the source is **time-averaged only**, no time dimension, offline, wrong file, or lacks verifiable coordinate/datum, emit explicit `SOURCE_NOT_ADMITTED` and leave prior v70 findings intact. Document limitations; no synthetic/mixed-year fallback, no biological movement or foraging outcome scoring in v71.

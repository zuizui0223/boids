# v64 frozen original WATLAS cross-taxon tide-heading SOURCE gate (no new biological effect)

**Frozen 2026-11-07 JST before any new v64 original-source quality/heading-eligibility counts are opened.** This is a deliberately *new ecological species* source audit, not a test or rewrite of prior Wadden Eurasian oystercatcher v43–v63 positive outcomes. Both candidate files were previously publicly documented for other aims; the v38 social-pair gate (red knot five tags, nine tideIDs, zero near-neighbour pairs) is already known. Source-only v64 asks a different feasibility question: does either dataset contain enough *within-animal* repeated temporal GPS/ATLAS three-point movements with tide labels to support a future out-of-tide-cycle direction forecast? **Do not fit/inspect next-heading outcomes in v64.**

## Two independently identified, published source files

- **Primary: red knot** (*Calidris canutus*), original WATLAS supplementary Additional File 14: DOI [10.6084/m9.figshare.26553446.v1](https://doi.org/10.6084/m9.figshare.26553446.v1), Figshare article `26553446`. Previously audited by v38: 7,595 raw rows, five TAG IDs, nine tideID values, 1,093 original TAG × 30s bins. Retain these facts as prior knowledge, never count them as proof of new v64 directional observability.
- **Companion: sanderling** (*Calidris alba*), original WATLAS supplementary Additional File 13: DOI [10.6084/m9.figshare.26553443.v1](https://doi.org/10.6084/m9.figshare.26553443.v1), Figshare article `26553443`. No presumption about its unknown row/bird/tide-cycle support.
- These are different shorebird species and instrument from the original 2010/2011 oystercatcher GPS. They are from **the same western Dutch Wadden Sea research programme**, not geographically independent. Source supplement extracts and 221-bird population Fig. 6 in the paper must not be conflated.

Only use the **single original published provider CSV** per article, selected by unique CSV suffix from Figshare article metadata. Require metadata article ID match, original `computed_md5` or `supplied_md5` if present and compare bytes, original byte count match, calculated SHA256; each file hard-stop if >150 MB. Read original TAG/TIME/X/Y/NBS/VARX/VARY/COVXY/tideID/tidaltime/waterlevel; no raw IDs, coords or times published. Individual GPS and detector hardware differ from historical oystercatcher GPS, so never transfer their fitted latitude/longitude ridge coefficients directly or declare the predictors physically equivalent.

## Raw source and temporal grain, fixed before audit

1. QC every original CSV row: TAG string nonblank; finite UNIX TIME between 2017-01-01 and 2023-12-31 UTC, finite UTM31 X ∈ [100000,900000], Y ∈ [4000000,7000000], NBS ≥3, and numeric variances VARX/VARY ∈ [0,5000] m², finite COVXY. Reject invalid rows from eligible source only and record aggregate drop reasons. Record missing tideID, missing/nonfinite tidaltime or waterlevel and duplicate original TAG-TIME rows separately. Preserve all original source rows in input denominator.
2. Original positions are grouped by `(TAG, floor(TIME/30))`; within a bin aggregate XY means *only from accepted original rows*. A bin is source-usable for tide covariates only when the **original tideID is unique and nonempty**, tidaltime is finite with within-bin spread ≤2 min, and waterlevel is finite with within-bin spread ≤5 cm; otherwise mark unavailable. Keep original distinct tag count, tideID count, tag-30s bin count; never fabricate interpolation or fill missing source tide.
3. Original **signed minutes relative to high tide** `tidaltime` is a temporal proxy only. Candidate "approaching high tide" = tidaltime in **[-300,-30] min**, "receding from high tide" = tidaltime in **[+30,+300] min**. Label these **proxy BEFORE/AFTER high**, NOT independently verified physical rising/falling slope or local inundation. A binary phase comparison is **not allowed** until both signed-support groups exist and later official 10-min gauge-slope validation. If the source encodes time past high as only nonnegative, report insufficiency; do not change the sign convention or wrap it after viewing source. `waterlevel` in cm belongs to the West-Terschelling gauge with published time offset and unverified datum at exact observed B. Do not claim local prey-front exposure.
4. For each TAG, sort bins by true original bin-start UNIX second. Create consecutive original three-bin A→B→C candidates with both gaps **30–180 seconds** inclusive, strictly increasing times, **same nonempty source tideID** for all three positions. Compute source-only Euclidean A→B and B→C *distance magnitudes* in UTM metres and require both speeds in **[0.2,30] m/s**; the B→C **heading/angle is never read or stored**. The middle B must have the complete original tide/proxy/waterlevel support. At most **one candidate triple per (TAG, B time)**. Report candidate count by source availability stage, phase-proxy counts, original participating TAG count and distinct tideIDs. Do not silently reduce eligible frequency or create interpolated new points.
5. **Out-of-cycle feasibility** is essential. For each candidate tideID, count distinct original TAGs and eligible triple records, and signed proxy groups. For a single species to be `SOURCE_FEASIBLE_FOR_SEPARATE_PREREGISTERED_TIDAL_FORECAST`, freeze all of: **≥120 three-bin direction-eligible source triples**, **≥3 TAGs**, **≥4 original tideIDs**, **at least 30 triples in each signed high-tide-side window**, **at least 2 different original tideIDs contributing each window**, and **at least two tideIDs with ≥20 eligible triples each to serve as heldout cycles**. This gate is only opportunity for a future **different model trained on old cycles, evaluated on untouched cycles**; no outcome/projection is computed here. Count all per-stage failures, keep both species even if one is NOT_ADMITTED. The source stage may show many raw rows but very few consecutive trips; do not lower thresholds or choose another time bin after seeing the counts.

## Public outputs, interpretation and future test

Output only anonymous aggregates per taxon: original published record ID, provider filename, original MD5-verified yes/no, SHA256, raw/QC/binned count, number of tags, distinct tide IDs, phase-proxy support, 3-fix eligibility and source admission, checksum of code commit. Do **not** commit/publish individual source tag IDs, original coordinates, timestamps, raw observations, per-TAG/per-tideID trajectories or actual B→C heading. Do not report causal tide-affected turning, source-waterline pursuit, social Boids force, training transfer or predictive gain.

**If one or both source gates pass:** a new v65 endpoint must first be separately frozen (actual tide-height control, own motion history, chronological tideID holdouts, matched-phase placebo, test-bird uncertainty); then check how the signed proxy relates to independently observed RWS physical gauge phase before scoring. If both fail: retain prior v43–v63 positives and the published red-knot tidal *space-use* association, report the new instrument/data-resolution limitation, and search the larger non-summary WATLAS localization archive instead of pretending it has been tested.

No external species effect is claimed by this protocol; Draft PR stacked on v63; main unchanged.

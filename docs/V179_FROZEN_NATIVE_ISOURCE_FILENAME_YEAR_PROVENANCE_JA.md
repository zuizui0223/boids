# v179：真の原isourceファイル出自年で2018/2019 GPS×歴史地形を追加監査（結果前固定）

2026-11-17。v178 GitHub Actions #44034996006（成功）は、元2018年157,863件から149,446件（94.668%）、元2019年125,241件から119,778件（95.638%）の同一20mセル元z/isourceへ対応した。鳥IDはそれぞれ35・27、すべて6〜9月の少なくとも3か月、曖昧重複タイル0。**これは地理・SOURCE対応であり、真の測量時刻・潮間帯干出・因果を示さない。**

## 追加の重大な未知点

RWS/Deltares NetCDF `time` の2017年などは「その年の状態」のアーカイブ時刻ラベルで、`isource(time,y,x)`は当該z画素の元ファイルへのゼロ始まり索引。`isource.flag_values`と`isource.flag_meanings`のネイティブCF属性には元ファイル名が入る場合がある。**2017ラベルの元画素を2018年の鳥に使っても、その画素の元ファイル名に2019年以後が含まれていれば未来情報の持ち込みとなる。** よって2017 TIMEラベルだけで「2017年の測量」と言わない。

## 固定した検証とSTOPルール

1. v178の認証済みゼノドー元GPS/ACC、RWS 2018/19潮位とDeltaresネイティブ10地形タイルをSHA/元ファイル条件に沿って再取得する。既存v178の**latest-valid-z+isource at identical native 20m cell, preceding max six calendar years**をいっさい変更しない。特定の出自に不利だからと旧年の別層へ戻って補完することを禁止。
2. 各v178で採択された**同一**画素・元`isource`数値を、同じタイルの元`isource.flag_values`→`flag_meanings`へ紐付ける。出自索引の欠落、欠損属性、重複索引、年月を復元できない元ファイル名は**UNKNOWNとして保留**。ソース名の四桁西暦又は明示されたYYYYMMDDを抽出し、複数年があれば最も新しい年を採用。 `2015_16tmp`は2016年を上限とする。 `22_8_1`など二桁のみの省略年は推測しない。
3. 元ファイル名から得た最新年が鳥のGPS観測年**未満**のみを`PREYEAR_FILENAME`として残し、同年・将来名は`SAME_OR_FUTURE_FILENAME_REJECTED`。不明は`UNKNOWN_FILENAME_REJECTED`。元ファイル名の年は**測量の実日付の証明ではない**。
4. v178での真GPS一致数2018=149,446、2019=119,778と再解析結果が**完全一致**しなければSTOP。採択 `PREYEAR_FILENAME` の元GPS×15分ビンが各年20,000以上、個体が各年10羽以上、各年6〜9月のうち3か月以上、タイル重複0で初めて「ファイル名年に関して入場」。閾値後調整、否定年・島の除外、未知名を便宜的に古年とする扱いは禁止。
5. GitHubへ保管するのは**年・月・元ファイル名年分類と出典フラグ項目数の集計のみ**。元GPS座標、鳥ID、実ACC、水位の個票、DEM画素値・2D配列、個体別時刻列、ソース名の個体別リンクは保存しない。

## 科学的判定階層

- `SOURCE_PASS`: v178の地形有効性＋v179の出典ファイル名年（観測年より前）の一致が元GPS記録で十分。
- `SOURCE_STOP`: ファイル名が未来・同年、出典不明、元GPS一致数変更、個体・月不足を本物の欠落として保持。**不都合な数値のために別の地形年へ置換しない**。
- 次の機構テストにはなお独立の鉛直基準（RWS NAP vs NetCDF z）、港から各採餌地点までの水位位相・振幅差、地形測量日と地形変動、真の採餌・餌密度及び天気・月光・昼夜の交絡対策が必要。
- 先行のオイスターキャッチャー潮位・干潟資源選択研究があるため、「潮汐に反応する」という一般命題だけでは新規性が弱い。仮に機構を扱う場合は**自己行動履歴を条件付けた未知年予測で、港湾水位の効果が地点ごとの利用可能干潟面積や局所水深の指標によりどれだけ説明されるか**を事前登録し、原行動・移動のBoids社会力と混同しない。

**v179では局所干出・局所水深・潮汐×太陽の生物因果・Boids力は計算しない。出自ファイル名の年が整合しても実測日の出典が別途必要。**
